# Harmonia v2 — presets « écoutés » et compréhension du français

La v2 remplace l'approche v1 (bert-tiny → 20 paramètres, appris sur 100 concepts écrits à la main) par un modèle qui **a écouté** ce que produit réellement le synthé.

## Idée générale

```
                    entraînement (hors ligne)                               production (ONNX, CPU)
┌────────────────────────────────────────────────────────────┐   ┌──────────────────────────────────────────┐
│ 200 000 presets ──► moteur Python (= Synth.cpp) ──► audio   │   │ prompt FR/EN                              │
│                                       │                     │   │   │                                       │
│                         CLAP (LAION) écoute ──► embeddings  │   │   ▼ encodeur multilingue int8 (~1,5 ms)   │
│                                                             │   │ vecteur « espace CLAP »                   │
│ 66 000 descriptions EN ──► traduction FR (opus-mt)          │   │   │                                       │
│     │                                                       │   │   ├─► recherche dans la banque (CSLS)     │
│     └─► distillation : MiniLM multilingue ≈ CLAP texte      │   │   └─► prédicteur de paramètres            │
│                                                             │   │           ▼                               │
│ FSD50K (51 000 sons réels) ──► presets qui les imitent      │   │ preset (20 paramètres)                    │
│     └─► prédicteur texte → paramètres                       │   └──────────────────────────────────────────┘
└────────────────────────────────────────────────────────────┘
```

- **Moteur de rendu** (`src/synth/`) : portage Python/numba de `Synth.cpp` + reverb de `PluginProcessor.cpp` + conversions JUCE des paramètres. Validé échantillon par échantillon contre le vrai code C++ compilé avec JUCE (écart RMS relatif médian 4e-4). `ENGINE_APP_1_0` reproduit l'app jusqu'à 2026-10, `ENGINE_APP_1_1` l'app corrigée (Harmonia-App#40).
- **Banque** (`scripts/v2/build_preset_bank.py`) : presets tirés de trois sources (concepts de `synthesize_dataset.py`, archétypes d'enveloppes/timbres, uniformes), joués sur La2 et La4, « écoutés » par CLAP (`laion/larger_clap_general`).
- **Encodeur de texte** (`scripts/v2/train_text_encoder.py`) : `paraphrase-multilingual-MiniLM-L12-v2` distillé pour reproduire l'embedding texte de CLAP, à partir de la phrase anglaise *et* de sa traduction française.
- **Prédicteur** (`scripts/v2/train_predictor.py`) : MLP embedding → 20 paramètres (têtes charte : sigmoïde, softmax pour les choix discrets), appris sur (texte → preset le plus proche à l'écoute) pour le corpus et pour les sons réels de FSD50K.
- **Inférence** (`src/v2/inference.py`) : ONNX Runtime + `tokenizers` + numpy uniquement. Trois modes : `retrieval` (meilleur preset de la banque, **par défaut**), `hybrid` (top-32 de la banque reclassé par accord avec le prédicteur), `neural` (sortie du prédicteur). `variation` (entier) tire une variante parmi les meilleurs candidats. Chargement 0,4 s, ~8 ms par requête sur CPU.

## Résultats (v2.0)

Benchmark de 70 prompts (27 instruments, 23 bruitages, 12 scènes composées, 8 ambiances), chacun en anglais et en français écrit à la main, retirés de toutes les données d'entraînement. Juge indépendant : Microsoft CLAP 2023. « Texte » = similarité son ↔ description ; « Réel » = similarité à de vrais enregistrements FSD50K eval de la même catégorie (51 prompts).

| Système | Texte EN | Texte FR | Réel EN | Réel FR |
|---|---|---|---|---|
| **v2 recherche (défaut)** | **0,234** | **0,225** | **0,387** | 0,370 |
| v2 hybride | 0,214 | 0,216 | 0,376 | **0,374** |
| v2 prédicteur seul | 0,161 | 0,162 | 0,341 | 0,338 |
| Professeur CLAP sur la banque complète (borne de référence) | 0,224 | — | 0,359 | — |
| v1 synthetic, app actuelle | 0,058 | −0,006 | 0,236 | 0,191 |
| v1 charter, app actuelle | 0,000 | −0,020 | 0,184 | 0,169 |
| Preset aléatoire | 0,014 | 0,025 | 0,193 | 0,200 |

- v2 recherche − v1 actuelle : **+0,176 en anglais** (IC 95 % [0,145 ; 0,210]) et **+0,231 en français** (IC 95 % [0,193 ; 0,270]) ; la v2 gagne sur 91 % (EN) et 93 % (FR) des prompts.
- Recherche − hybride : +0,020 en anglais (IC 95 % [0,006 ; 0,034]), non significatif en français et sur « Réel ». La recherche est donc le mode par défaut.
- En français, la v1 est en dessous du hasard (−0,006) et franchement négative sur les bruitages (−0,138) ; la v2 y obtient 0,214.
- Encodeur multilingue (validation, 1 500 phrases) : cosinus au professeur 0,84 (EN) / 0,80 (FR), bonne phrase retrouvée 82 % / 70 %.

Limites : le synthé n'a que 20 paramètres (pas d'enveloppe de pitch, de taille de reverb, de résonateurs) ; « verre qui se brise » ou « lead supersaw » restent des approximations. Un moteur plus riche se ré-entraîne avec le même pipeline (nouvelle banque).

## Garde-fous de qualité

- Presets quasi inaudibles (< -40 dBFS au-dessus de 60 Hz) exclus : ils « ressemblent à tout » pour CLAP.
- Correction CSLS des *hubs* (presets proches de toutes les descriptions), réglée sur FSD50K **eval** (`scripts/v2/tune_retrieval.py`), jamais sur le benchmark.
- Les prompts du benchmark sont retirés de toutes les données d'entraînement (`src/v2/benchmark_set.py`).
- Benchmark noté par un **juge indépendant** (Microsoft CLAP 2023), jamais utilisé à l'entraînement : score texte ↔ audio et similarité à de vrais enregistrements FSD50K eval.

## Commandes

```bash
make setup-train                 # dépendances d'entraînement (requirements-train.txt)
make v2-train FSD50K=~/Datasets/FSD50K   # enchaîne toutes les étapes ci-dessous, dans cet ordre
#   v2-bank         banque de presets écoutés par CLAP
#   v2-fsd50k       sons réels FSD50K (dev pour l'entraînement, eval pour le réglage)
#   v2-corpus       corpus anglais + traduction française
#   v2-text         encodeur multilingue (8 époques)
#   v2-analyze      volume audible + score « hub » de chaque preset
#   v2-tune         réglage CSLS sur FSD50K eval
#   v2-predictor    prédicteur
#   v2-tune-hybrid  réglage du mode hybride
#   v2-export       export ONNX (models/harmonia_v2)
make v2-bench                    # benchmark (juge dans .venv-judge, voir benchmark_judge.py)
make v2-package V2_TAG=ai-v2.0.0 # archive + models/release.json
make v2-fetch                    # télécharge le modèle épinglé dans models/harmonia_v2/
```

Temps mesurés sur MacBook M4 Pro (MPS), étapes seules : banque de 200 000 presets ≈ 75 min, FSD50K ≈ 12 min, traduction ≈ 15 min (CPU), encodeur 8 époques ≈ 25 min, prédicteur ≈ 3 min, export ≈ 2 min. Tous les scripts utilisent CUDA si disponible (RTX 5070).

## API

`POST /generate` (et `/ai/generate-preset`) avec `model_name` = `harmonia_v2` (alias `model-3`, `v2`, `3`) :

```json
{"prompt": "porte qui claque dans une cathédrale", "model_name": "harmonia_v2", "variation": 3}
```

La réponse a le même format que la v1 (`metadata`, `parameters`, `values`, `charter`) plus `generation` (`mode`, `bank_index`, `similarity`). Les prompts ne sont plus rejetés au-delà de 32 tokens (troncature à 64).

## Distribution

Les fichiers du modèle (~150 Mo) ne sont pas dans git : ils sont publiés en asset de release GitHub et épinglés (tag + sha256) dans `models/release.json`. `scripts/v2/fetch_model.py` télécharge et vérifie chaque fichier ; le Dockerfile l'appelle au build. Ils sont rangés dans `models/` et non `saved_models/`, que le VPS remplace par un volume.
