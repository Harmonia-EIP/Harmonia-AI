# Harmonia v4 — des données mieux choisies, le même moteur

Suivi : [#35](https://github.com/Harmonia-EIP/Harmonia-AI/issues/35) (texte : #37, générateur : #38).

La v4 garde tout ce qui tourne sur le VPS et dans le plugin : la charte v3 (192 paramètres), le moteur
analogique et le mode DX7, et le même code d'exécution (`src/v3/inference.py`). Seuls les poids changent,
appris sur des données mieux choisies. Le plugin actuel joue donc les presets v4 sans changement, et une
génération coûte le même temps qu'en v3.3.

## Où la v3.3 perdait (mesuré avant de rien entraîner)

**Côté texte** (`scripts/v4/text_gap.py`, sans rien jouer). On compare le son visé par un texte au vrai son
sur 2 000 descriptions humaines d'enregistrements FSD50K du jeu d'évaluation, jamais vues à l'entraînement :

| Encodeur de texte | similarité cible ↔ vrai son | vrai son dans le top 10 sur 2 000 |
|---|---|---|
| v3.3 (encodeur multilingue distillé) | 0,471 | 44,4 % |
| CLAP d'origine (anglais seulement, trop lourd pour le VPS) | 0,492 | 52,9 % |

L'encodeur multilingue a appris sur des titres, des étiquettes et des noms de presets, jamais sur des
phrases : sur des descriptions en langage courant, il ne reproduit CLAP qu'à 0,71 de similarité.

**Côté son**. Même modèle, mais la cible est le vrai son de la classe (moyenne CLAP de ses enregistrements de
développement) au lieu de la cible tirée du texte. Juge indépendant, 165 classes FSD50K :

| | classes, texte | classes, réel |
|---|---|---|
| v3.3 | 0,103 | 0,352 |
| v3.3 avec la cible parfaite | 0,108 | 0,370 |
| vrais enregistrements | | 0,714 |

L'écart n'est pas significatif : sur les noms de classes, le texte ne limite pas (le « prior » les connaît
déjà, top 5 : 94 %). Ce qui limite, c'est ce que le générateur et le moteur savent produire pour une cible.

Donc :
- **texte** : apprendre des phrases, pour les prompts en langage courant ;
- **son** : donner au générateur analogique plus d'exemples cible → preset (il n'avait que 2 117 presets de
  banque et 388 imitations).

## Sources étudiées et choisies

| Source | Pour quoi | Licence | Décision |
|---|---|---|---|
| Descriptions FSD50K (jeu de développement) | encodeur de texte et « prior » | CC0 / CC BY seulement | **oui**, nettoyées |
| Imitations FSD50K restantes | générateur analogique | CC0 / CC BY seulement | **oui**, mêmes filtres que la v3.3 |
| NSynth (notes d'instruments étiquetées) | générateur analogique | CC BY 4.0 | **pas dans la v4** (voir plus bas) |
| Clotho (légendes de scènes sonores) | — | légendes sous licence de l'université de Tampere, surtout non commerciale | **non** |
| API Freesound | — | par enregistrement | **plus tard** : FSD50K en est déjà une sélection vérifiée |
| Lots SFX Hugging Face / Zenodo | — | variable, souvent floue | **non** |
| Descriptions générées par un modèle (captioning, LLM) | — | — | **non** : texte humain uniquement |

Clotho est écarté pour deux raisons : ses légendes ne sont pas réutilisables commercialement, et ce sont des
scènes de 15 à 30 s (« une voiture passe pendant que des oiseaux chantent »), pas des sons qu'un preset peut
jouer.

## Descriptions nettoyées (`src/v4/descriptions.py`, `scripts/v4/build_corpus_v4.py`)

Les personnes qui déposent un son sur Freesound le décrivent avec leurs mots (« The slow rattling of a
cardboard matchbox filled with wooden matches »), mais le même texte parle aussi du micro (« Recorded on a
tascam DR-40 »), des liens, de la licence ou des remerciements. On garde les deux premières phrases qui
parlent du son lui-même, mot pour mot. Une phrase est retirée quand :
- elle parle du matériel, du logiciel, du format, de la licence ou d'autres sons de l'auteur ;
- elle n'est pas en anglais ;
- elle revient dans plus de 3 descriptions (texte type d'un pack).

Résultat : 13 465 enregistrements CC0 ou CC BY du jeu de développement gardent une description (12 116
textes différents), traduite en français par le même traducteur local que la v3. Les prompts de test de Malo
sont exclus. Le jeu d'évaluation reste de côté pour les mesures.

## Encodeur de texte et « prior » v4 (#37)

L'encodeur de texte est réentraîné à l'identique de la v3 (`scripts/v2/train_text_encoder.py`, 8 époques)
sur le corpus v4. Le « prior » garde le modèle et la perte de la v3 (`scripts/v4/train_prior_v4.py`) ; il
apprend en plus les paires description → enregistrement. Mesure `text_gap.py` sur le jeu d'évaluation :

| Encodeur + prior | descriptions EN : similarité / top 10 sur 2 000 | descriptions FR : similarité / top 10 sur 500 | noms de classes : top 5 |
|---|---|---|---|
| v3.3 | 0,471 / 44,4 % | 0,465 / 65,0 % | 93,9 % |
| v3.3 + prior avec descriptions | 0,486 / 45,2 % | 0,482 / 67,8 % | 92,7 % |
| v4 + prior paires v3 | 0,501 / 49,0 % | 0,492 / 69,4 % | 93,3 % |
| v4 + prior avec descriptions | 0,521 / 52,0 % | 0,506 / 71,2 % | 90,9 % |
| v4 + prior, FSD50K CC0/CC BY seulement | 0,512 / 51,1 % | 0,500 / 71,2 % | 92,1 % |
| **v4 retenu** : prior CC0/CC BY + accord CLAP ≥ 0,10 | **0,520 / 51,2 %** | **0,510 / 72,8 %** | **93,3 %** |
| (CLAP d'origine, anglais seulement) | 0,492 / 52,9 % | — | — |

L'essentiel du gain vient de l'encodeur, qui apprend enfin des phrases. En anglais, il rattrape presque
CLAP d'origine, pour environ 4 fois moins de calcul et en comprenant le français. Le « prior » retenu
n'apprend plus que sur des enregistrements CC0 ou CC BY (la v3 utilisait aussi des CC BY-NC et Sampling+). Il
écarte aussi les 890 paires description → son que CLAP juge sans rapport (« accord » : similarité CLAP entre
le texte et le son). Contrôle : réentraîné avec les seules paires v3, il redonne exactement la v3.3.

## Pourquoi pas NSynth dans la v4

NSynth (CC BY 4.0) donne 300 000 notes d'instruments étiquetées (famille, source, « bright », « dark »…).
Les imiter sur le moteur analogique demanderait de jouer chaque note à sa hauteur. Surtout, la plupart sont
des instruments acoustiques (guitare, flûte, cordes) imités par un synthé soustractif : le générateur
risquerait d'apprendre des presets que CLAP trouve proches sans qu'ils sonnent juste. La règle de la v4 est
« aucune régression sur le son » : NSynth reste un essai à part (#38), à valider à l'écoute.

## Mesurer

- `scripts/v4/text_gap.py` : la partie texte seule, sans rien jouer (quelques secondes) ;
- `scripts/v3/benchmark_v3.py --sets malo,fsd,desc,desc_fr` puis `scripts/v3/benchmark_judge_v3.py` : la
  génération complète jugée par MS-CLAP, sur les prompts de Malo, les 165 classes FSD50K, et 100 descriptions
  mises de côté en anglais (`desc`) et en français (`desc_fr`). Pour une description, le juge compare le son
  au texte et à l'enregistrement décrit.

## Commandes

```bash
python scripts/v4/build_corpus_v4.py
python scripts/v2/translate_corpus.py --inp data/v4/corpus_todo.jsonl --out data/v4/corpus_todo_fr.jsonl
python scripts/v4/build_corpus_v4.py --merge
python scripts/v2/train_text_encoder.py --corpus data/v4/corpus_en_fr.jsonl --out data/v4/text_student
python scripts/v4/train_prior_v4.py --out data/v4/prior/desc_free.pt --free-only
python scripts/v4/text_gap.py --student data/v4/text_student --prior data/v4/prior/desc_free.pt
```
